# Visual MCP Auth + Status Visibility (Linear / GitHub / Notion)

## Summary
Make the three inbuilt remote MCPs (linear, github, notion) visible in the status UIs and authentable with a click/keypress instead of the CLI. Desktop app already has click-to-auth wiring once servers are visible; the terminal TUI has no visual auth at all. Fix visibility root cause first, then add the missing TUI auth trigger plus pending/failure UX on both surfaces.

## Context / Findings
- Builtins live in `packages/opencode/src/config/config.ts` (`builtinMcp`, `enabled: false`, `oauth: {}`), merged first in `loadInstanceState`, so user config can override. No network I/O at startup by design.
- `MCP.status()` (`packages/opencode/src/mcp/index.ts:591-608`) lists all configured servers including `disabled`; nothing filters them. A fresh backend must return 3x `disabled`.
- The screenshot (`packages/app/.../status-popover-body.tsx:400-407`, empty text from `packages/app/src/i18n/en.ts:325`) shows an empty map, which means one of: stale backend predating `builtinMcp` / cached per-directory `InstanceState`, wrong `directory`/`workspace` in the status query, or stub config. It is not a UI filter bug.
- Data flow: `Config.get().mcp` -> `MCP.status()` -> `GET /mcp` (`packages/opencode/src/server/routes/instance/httpapi/handlers/mcp.ts`) -> TUI `packages/tui/src/context/sync.tsx:525` (one fetch at bootstrap) / desktop `packages/app/src/context/server-sync.tsx:93-113` (TanStack Query per directory).
- Desktop visual auth already exists: row click -> `toggleMcp` (`packages/app/src/context/global-sync/mcp.ts`, `server-sync.tsx:693-723`, `needs_auth -> sdk.mcp.auth.authenticate()`), amber dot + `mcp.auth.clickToAuthenticate` hint (`status-popover-body.tsx:429-441`).
- TUI has no visual auth: `local.mcp.toggle` (`packages/tui/src/context/local.tsx:505-520`) only does connect/disconnect, so `needs_auth` loops back to itself plus an 8s toast saying `Run: opencode mcp auth <key>` (`mcp/index.ts:312-321`). `DialogMcp` (`packages/tui/src/component/dialog-mcp.tsx`) and `DialogStatus` (`packages/tui/src/component/dialog-status.tsx`) show raw status text.
- HTTP endpoints for all auth steps already exist (`authStart` returns URL, `authCallback` accepts pasted code, `authAuthenticate` blocks on browser+callback). Nobody subscribes to `BrowserOpenFailed`, so a failed browser-open hangs silently.

## Approach
Keep `enabled: false` default (zero-I/O startup). Treat this as two gaps: (1) visibility/refresh — diagnose stale-backend vs workspace mismatch, harden refresh; (2) visual auth — mirror the desktop `toggleMcp` map (`needs_auth -> authenticate`) into the TUI, and add pending + browser-failure + manual-code fallback UX on both surfaces using existing endpoints. No SDK regen (reuse `authStart`/`authCallback`/`authAuthenticate`).

## Files affected
- `packages/opencode/src/config/config.ts` — only if diagnostics show user config can wipe builtin keys; re-assert `{ ...builtinMcp, ...result.mcp }` after merges.
- `packages/app/src/components/status-popover-body.tsx` — pending text while authenticating; toast/modal with URL + copy on `BrowserOpenFailed`; manual-code input calling `authCallback`.
- `packages/app/src/context/server-sync.tsx` — surface `BrowserOpenFailed`/status-change events into query invalidation + toast.
- `packages/tui/src/context/local.tsx` — `mcp.toggle`: `needs_auth -> sdk.client.mcp.auth.authenticate()`; add `mcp.authenticate()` helper.
- `packages/tui/src/component/dialog-mcp.tsx` — `needs_auth` description/action ("authenticate"), waiting state, refresh after.
- `packages/tui/src/component/dialog-status.tsx` — replace raw `run: opencode mcp auth` hint with keypress hint; surface `BrowserOpenFailed` URL via toast/log.
- `packages/tui/src/context/sync.tsx` — subscribe to `mcp.browser_open_failed` like the existing `lsp.updated` subscription.

## Step-by-step implementation
1. Reproduce visibility: fresh backend (`bun run ./src/index.ts serve --port 4096` from `packages/opencode`), `opencode mcp list` and `GET /mcp?directory=<dir>` must show 3x `disabled`. If empty, confirm backend age, `OPENCODE_DISABLE_PROJECT_CONFIG` / `OPENCODE_CONFIG_CONTENT`, and the `directory` param the UI sends.
2. Backend hardening (only if step 1 shows wipe): re-assert builtin keys after all config merges; keep `enabled: false` unless user sets `true`.
3. Desktop: pending row state during `authAuthenticate` (up to 5-min callback wait); on `BrowserOpenFailed`, show URL with copy + manual open; manual `code` paste -> `authCallback`; keep existing `refresh()` of `mcp` + `mcpResources` queries.
4. TUI: implement `needs_auth -> authenticate` in toggle, distinct `authenticate` action, waiting indicator, post-auth `mcp.status()` refresh; event subscription for `browser_open_failed` with URL toast; manual-code fallback via `authCallback`.
5. Refresh: ensure desktop invalidates MCP query on `mcp.status.changed`/`ToolsChanged`; TUI re-fetches on dialog open and after toggle/auth.

## Risks / edge cases
- Stale `InstanceState` (per-directory cache) after upgrade — restart/dispose required; config edits need re-bootstrap.
- Wrong workspace snapshot yields empty map that mimics "no MCPs".
- `authenticate` blocks up to 5 min on callback wait — UI must show pending + allow retry/cancel; concurrent auths race the single `oauth-callback` port singleton — one at a time.
- Headless/SSH with no browser — manual URL open + pasted-code path must work; never log tokens.
- `needs_client_registration` must surface error + docs, not loop into `authenticate`.

## Testing strategy
- `opencode mcp list` shows 3x `disabled` on fresh dir; `GET /mcp` same; desktop MCP tab and TUI dialogs list 3 rows (no "No MCPs configured").
- Toggle `linear` disabled -> `connect` -> `needs_auth` (amber + hint); click/Space -> browser opens -> approve -> `connected`, tools listed, switch ON.
- Browser-open killed/headless: URL toast/modal appears; manual open completes; pasted code via `authCallback` completes.
- `disconnect` -> `disabled`; reconnect with stored tokens -> `connected` without browser.
- No outbound traffic to linear/githubcopilot/notion hosts while all three disabled; `bun typecheck` in `packages/opencode`, `packages/app`, `packages/tui`; existing MCP/config/sync tests pass.
