# Permission request notifications

## Root Cause

The desktop native-notification transport is working, but its permission-event trigger exists only in the legacy layout (`packages/app/src/pages/layout.tsx`). The new layout is the default and renders the permission dock without subscribing to `permission.asked`, so an unfocused Forge window has no notification to show.

## Implementation

1. Move permission-alert handling into the shared `NotificationProvider` in `packages/app/src/context/notification.tsx`, which is mounted for both layouts and creates server-scoped listeners.
2. Listen for adapted `permission.asked` and `permission.replied` events for every connected server.
3. Add a narrow PermissionProvider actionability check in `packages/app/src/context/permission.tsx` that:
   - verifies the exact request is still pending;
   - awaits the existing session/directory/lineage auto-response resolution;
   - verifies it remains pending before allowing an alert.
4. For each actionable permission request, respect the existing permission notification and sound settings, reuse existing localized title/description strings, and call `platform.notify`. The desktop platform will suppress alerts while the Forge window is focused.
5. Deduplicate by directory, session, and permission ID; clear the key on reply. This prevents duplicate event alerts while allowing distinct simultaneous requests in the same session.
6. On notification click, open/select the corresponding session in the new layout and navigate to its server-qualified route in the legacy layout. Remove the legacy layout's duplicate permission notification branch after the shared listener takes over.
7. Leave desktop notification IPC and icon handling unchanged.

## Verification

1. Add focused app tests for actionable pending detection, auto-approval suppression, reply-during-lineage-resolution suppression, notification settings, deduplication, and click navigation.
2. Run affected app tests and `bun typecheck` from `packages/app`.
3. In desktop Forge, trigger a manual-mode permission while the window is unfocused and confirm the native notification appears; click it and verify Forge focuses on the requesting session.
4. Confirm no alert is sent for focused windows, disabled permission alerts, Auto/Accept Edits responses, or already replied requests.
