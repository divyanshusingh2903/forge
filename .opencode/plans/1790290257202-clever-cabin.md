# Native Linux notification icon

## Goal

Send desktop notifications through Electron's native main-process API so Linux receives Forge's bundled application icon rather than Chromium's renderer favicon. The reported problem is icon-only; Forge's existing desktop sender identity remains unchanged.

## Implementation

1. Export the existing packaged/development-aware Forge icon resolver from `packages/desktop/src/main/windows.ts`. It must resolve `resources/icons/icon.png` in development and `process.resourcesPath/icons/icon.png` in packaged builds.
2. Add a narrow desktop-notification IPC contract in `packages/desktop/src/preload/types.ts` and bridge it in `packages/desktop/src/preload/index.ts`:
   - Renderer sends an opaque notification ID, title, and body.
   - Renderer subscribes to notification-click IDs.
   - No renderer-controlled icon path or window ID crosses the boundary.
3. Register the notification handler in `packages/desktop/src/main/ipc.ts`:
   - Identify the originating `BrowserWindow` from the IPC sender.
   - Create and show Electron `Notification` with the exported local Forge icon path.
   - On click, show and focus that originating window, then notify its renderer using the opaque ID.
4. Replace the renderer `new Notification(...)` implementation in `packages/desktop/src/renderer/index.tsx`:
   - Preserve the existing focused-window suppression.
   - Maintain local ID-to-click-callback state so click behavior stays the same without serializing callbacks through IPC.
   - Invoke the native notification API and remove its callback after a matching click.
   - Remove the renderer favicon icon option, which is not a reliable Linux native notification asset.
5. Add focused test coverage for the native notification boundary, including payload icon path, `.show()`, click focus behavior, and callback delivery. Keep unrelated stale electron-builder identity-test cleanup out of this fix.

## Verification

1. From `packages/desktop`, run `bun typecheck` and the focused desktop notification tests.
2. Build a production Linux package with `OPENCODE_CHANNEL=prod bun run package:linux` and verify its bundled `resources/icons/icon.png` exists.
3. Install the produced package, leave Forge unfocused, and trigger a session notification. Confirm the visible notification icon is Forge and clicking it focuses the originating Forge window.
4. If a notification daemon still renders a stale/wrong image, capture the actual native payload with `dbus-monitor --session "interface='org.freedesktop.Notifications',member='Notify'"` while triggering it; confirm the icon argument points to the Forge bundled icon before diagnosing daemon cache behavior.
