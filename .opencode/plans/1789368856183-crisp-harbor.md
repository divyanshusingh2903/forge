# Fix Plan Tab Focus + Cross-Session Plan Leak

## Summary
Fix two plan-mode UI bugs: (1) proposing a plan (`present_plan` running) does not switch the side panel to the Plan tab, staying on Files Changed/review; (2) a session with no plan displays the last plan from the same project due to shared-directory fallback plus stale `.latest` reads.

## Context / Findings
- Tab auto-switch only in `packages/app/src/pages/session.tsx:414-419`: `void tabs().open("plan")` on `present_plan/running`. `open("plan")` only prepends to `all` (`packages/app/src/context/layout-tabs.ts:43-59`), never `setActive("plan")`, so `createSessionTabs/activeTab` (`packages/app/src/pages/session/helpers.ts:66-79`) still resolves to `review`/file tab.
- `openedForPresentPlan` etc. are plain per-component `Set`s (`session.tsx:391-394`), lost on remount; `status!=="running"` (completed/pending replay) never triggers.
- Plan tab content only in V2 branch of `session-side-panel.tsx:614-647,769-773`; legacy branch has no plan trigger/content; whole panel gated on `isDesktop()` (`session-side-panel.tsx:297`) so mobile has no surface.
- `Session.plan()` (`packages/opencode/src/session/session.ts:332-337`) is worktree-shared (`worktree/.opencode/plans/<created>-<slug>.md`), or globally shared when no VCS. `resolvePlanFile` (`session.ts:372-397`) falls back to newest `.md` with `mtime >= since` from ANY session when `expected` is missing.
- Callers do `planCycleAnchor(messages,info) ?? info` (`server/routes/instance/httpapi/handlers/session.ts:108-120`, `tool/plan.ts:46`), so a plan-less session scans the shared dir and returns another session's file with `exists:true`.
- Frontend `use-plan-info.ts:29-50,84-85` faithfully displays whatever path server returns; `.latest` read lingers previous session's `{path,exists}` across session switch; `file.load(path,{force:true})` + `session-plan-tab.tsx:46-66` renders leaked bytes; `session-plan-indicator.tsx:9-36` lights up.
- `reminders.ts:52-70,92-111` uses `existsSafe(plan)` directly with no fallback, so agent prompt correctly says no plan while UI says plan exists.

## Approach
Give pending `present_plan` priority in tab resolution and explicitly `setActive("plan")` once per `callID`; scope `resolvePlanFile` fallback to same-session slug and short-circuit the `plan` endpoint when there is no plan anchor, plus guard `usePlanInfo` against cross-session `.latest` reads. Preserves typo-recovery fallback (same slug) while blocking cross-session hits.

## Files affected
- `packages/app/src/pages/session.tsx` — add `tabs().setActive("plan")` next to `open("plan")`; hoist dedupe sets to module scope / key by session.
- `packages/app/src/pages/session/helpers.ts` — add optional `pendingPlan` input to `createSessionTabs`; prioritize `plan` over `review` fallback while pending.
- `packages/app/src/pages/session/session-side-panel.tsx` — ensure plan trigger/content in both layout branches; guard `previewTab/activateTab` from stealing focus while plan pending unless user-initiated.
- `packages/app/src/pages/session/composer/session-plan-question-dock.tsx` — `openPlan()` also `setActive("plan")`.
- `packages/opencode/src/session/session.ts` — `resolvePlanFile` accepts `slug`, filters fallback to `*-<slug>.md`.
- `packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts` — return `{path, exists:false}` early when `planCycleAnchor` is undefined (no scan).
- `packages/opencode/src/tool/plan.ts` — pass `slug` through to `resolvePlanFile`.
- `packages/app/src/pages/session/use-plan-info.ts` — guard `exists/path` memos by current sessionId + `planKey` session prefix; only render/auto-open on `exists:true`.

## Step-by-step implementation
1. Session tab focus: in `session.tsx:415-418` add `tabs().setActive("plan")` after `open("plan")`; hoist `openedForPresentPlan/handled*` sets to module-level `Map<sessionId,Set>` so remounts don't refire.
2. Tab priority: extend `TabsInput` in `helpers.ts` with `pendingPlan?: Accessor<boolean>` (default `()=>false`); in `activeTab` memo return `"plan"` when `pendingPlan() && planOpen()` before `review` fallback.
3. Side panel: verify/add plan `Tabs.Trigger/Content` in legacy branch to match V2 (`~769`); in `previewTab/activateTab` skip `setActive(review|file)` when `pendingPlan()` true unless from explicit user click.
4. Dock button: in `session-plan-question-dock.tsx:openPlan` add `tabs().setActive("plan")`.
5. Mobile fallback: if `!isDesktop()` and `present_plan/running`, show toast with `Open plan` action reusing `planPath/pendingRequest` (or open bottom sheet hosting `SessionPlanTab`).
6. Backend scoping: add `slug: string` param to `resolvePlanFile`; filter `entry.name.endsWith('-'+slug+'.md')` in fallback loop.
7. Endpoint guard: in `handlers/session.ts:plan`, use `const anchor = Session.planCycleAnchor(...); if (!anchor) return {path: Session.plan(info,instance), exists:false}` without scanning; else pass `slug: anchor.slug`.
8. Tool path: in `tool/plan.ts:46-52` pass `slug: (anchor ?? info).slug`; audit `reminders.ts` similarly.
9. Frontend guard: in `use-plan-info.ts:84-85` replace `.latest` reads with session-keyed memo: only return `exists/path` when `planKey()?.startsWith(id+":")` and resource ready; gate `SessionPlanTab` render + auto-open on `exists`.
10. Verify fork case: forked session (new slug, cloned messages) must not resolve to parent plan via fallback (slug filter handles it).

## Risks / edge cases
- Multiple `present_plan/running` callIDs (Revise loop): `setActive` once per callID is correct; completion (Accept/Deny) must NOT force back to review.
- User explicitly clicking review comment/file during pending plan must still win over auto-focus guard.
- Model hand-wrote wrong-timestamp path: preserved via same-slug suffix match, still resolves.
- Non-VCS global plans dir (`Global.Path.data/plans`): slug filter is mandatory, all projects share dir.
- `planInfo.latest` Suspense avoidance: keep `.latest` pattern but add session-prefix guard so no whole-view blanking.
- Legacy layout + mobile branches need manual verification (no plan content currently).

## Testing strategy
- Manual: start plan-mode session, trigger `present_plan` with review data present → Plan tab becomes active, panel opens on desktop; toast/bottom-sheet on mobile.
- Manual: create Session B after Session A plan in same project, never enter plan mode in B → Plan tab empty, indicator off; switch A→B rapidly → no flash of A's plan in B.
- Manual: typo-timestamp plan file (same slug, different timestamp, mtime newer) still resolves.
- Run relevant checks from package dirs (never repo root): `bun typecheck` in `packages/app` and `packages/opencode`.
