# Integrate Linux Title Bar into the UI

## Summary
Remove Electron's native Linux window frame and use the existing in-app title bar as the window chrome. Add localized minimize, maximize/restore, and close controls while preserving the current Windows and macOS behavior.

## Context / Findings
- `packages/desktop/src/main/windows.ts` applies `frame: false` only to Windows; Linux therefore retains its native title bar.
- The shared renderer title bar is `packages/app/src/components/titlebar.tsx` and has both legacy and V2 branches.
- Linux currently has no renderer window controls; its native frame supplies them.
- Existing `window.minimize`, `window.toggleMaximize`, and `window.close` actions are implemented in `packages/desktop/src/main/desktop-menu-actions.ts` and exposed through `runDesktopMenuAction`.
- Maximize state currently has no preload/renderer synchronization API; fullscreen state provides an existing pattern.
- Existing drag-region CSS makes interactive descendants non-draggable. Linux controls must remain explicitly non-draggable and RTL-safe.

## Approach
Make Linux frameless in the main-process `BrowserWindow` configuration, then add a reusable Linux-only control group to both titlebar variants. Route all actions through the existing desktop menu action bridge, and add main/preload/renderer maximize-state synchronization so the toggle button accurately changes between maximize and restore. Keep native titlebar behavior unchanged on Windows and macOS.

## Files affected
- `packages/desktop/src/main/windows.ts` — set Linux windows frameless; emit maximize/unmaximize state and expose initial state.
- `packages/desktop/src/main/ipc.ts` — register the initial maximize-state IPC handler and window-state event bridge as needed.
- `packages/desktop/src/preload/types.ts` — type maximize-state query/subscription APIs.
- `packages/desktop/src/preload/index.ts` — expose maximize-state APIs to the renderer.
- `packages/desktop/src/renderer/window-maximized.ts` — add reactive initial/event synchronization, mirroring fullscreen state.
- `packages/desktop/src/renderer/index.tsx` — provide maximize state through the desktop platform object.
- `packages/app/src/context/platform.tsx` — add optional window-maximized accessor to the platform contract.
- `packages/app/src/components/titlebar.tsx` — render Linux window controls in legacy and V2 titlebars, with localized labels and correct maximize/restore state.
- `packages/ui/src/components/icon.tsx` and/or `packages/ui/src/v2/components/icon.tsx` — add/reuse suitable minimize, maximize, restore, and close icons if the current icon set lacks them.
- Relevant desktop/app tests — cover window actions, state synchronization, platform-specific rendering, and both titlebar variants.

## Step-by-step implementation
1. Update Linux `BrowserWindow` options to use `frame: false`, without applying Windows-only titlebar overlay settings.
2. Add main-process maximize/unmaximize notifications and an initial maximized-state IPC query using Electron's authoritative window state.
3. Extend preload types and exposure, then add the renderer reactive accessor and wire it into the desktop `Platform` implementation.
4. Add a shared internal `WindowControls` titlebar component that dispatches `window.minimize`, `window.toggleMaximize`, and `window.close` through `runDesktopMenuAction`.
5. Render controls only on Linux in both legacy and V2 titlebar branches; use existing i18n keys for minimize/maximize/close and add a restore translation key only if required by the typed translation layer.
6. Use logical-end placement, accessible focus/hover states, adequate pointer targets, and explicit `app-region: no-drag` so controls work in LTR/RTL, X11, and Wayland.
7. Add focused tests for menu action toggling, maximize state initialization/events, Linux-only controls, button dispatch, and maximize-versus-restore labeling/icon state.
8. Manually validate packaged/dev Linux behavior on X11 and Wayland: drag, minimize, maximize/restore, close, startup maximized, fullscreen, zoom, multiple windows, and RTL layout.

## Risks / edge cases
- Frameless dragging and caption behavior can differ between X11 and Wayland; preserve draggable regions and do not infer maximized state from dimensions.
- A window restored maximized before renderer subscription needs the initial state query.
- Native menu actions and titlebar buttons must stay synchronized through the same action path.
- Linux controls must not consume the draggable region, and logical placement must remain correct in RTL.
- Existing Windows overlay and macOS traffic-light behavior must remain unchanged.

## Testing strategy
- Run focused desktop and app component tests from their package directories, never from the repository root.
- Verify both legacy and V2 titlebars render all three controls only on Linux and dispatch the expected actions.
- Verify maximize/unmaximize event and initial-state synchronization.
- Perform manual Linux X11/Wayland checks for window interaction, startup state, fullscreen, zoom, multiple windows, and LTR/RTL layouts.
