# Rebrand System-Prompt Identity to Forge

## Context

The active model-specific system prompts are selected by `SystemPrompt.provider` in `packages/opencode/src/session/system.ts`. Their opening identity lines currently call the agent `opencode` or `OpenCode` across `packages/opencode/src/session/prompt/*.txt`. The prompt files also contain legitimate OpenCode documentation, repository, feedback, and command references that should remain unchanged.

The user wants the agent to identify itself as `Forge` while explicitly stating that Forge is built on top of OpenCode. The repository has existing unrelated worktree changes, which will be left untouched.

## Design decisions

- Update the identity wording in every active provider prompt so all model routes consistently identify the agent as Forge and mention that it is built on top of OpenCode.
- Preserve OpenCode URLs, documentation guidance, feedback destinations, and CLI command names such as `opencode mcp auth`; those are product/integration references rather than the agent's self-identification.
- Leave the unused `copilot-gpt-5.txt` unchanged because it is not imported by `SystemPrompt.provider`.
- Add focused routing assertions to the existing system prompt test so the active provider variants cannot regress to identifying as OpenCode.

## Changes

- Modify these active prompt sources under `packages/opencode/src/session/prompt/`: `default.txt`, `anthropic.txt`, `beast.txt`, `gemini.txt`, `gpt.txt`, `gpt-astra.txt`, `kimi.txt`, `codex.txt`, `trinity.txt`, and `meta.txt`. Change only their self-identification text to use Forge and include the OpenCode foundation statement.
- Extend `packages/opencode/test/session/system.test.ts` with representative model IDs covering each prompt-selection branch, asserting that the selected prompt contains the Forge identity and does not use OpenCode as the agent name.
- Do not modify `packages/opencode/src/session/system.ts`; prompt routing already centralizes selection and requires no behavioral change.

## Out of scope

- Renaming the product, package names, URLs, documentation references, issue trackers, or executable/CLI command names.
- Updating generated distributions or the dormant Copilot prompt.
- Changing unrelated existing worktree modifications.
