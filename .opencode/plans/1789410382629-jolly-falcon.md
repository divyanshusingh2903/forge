# Orphaned present_plan recovery after restart

## Summary
After app restart, `present_plan` stays `running` (shimmer) but its `question.ask` rendezvous is gone, so Accept/Revise/Deny never appears. Add explicit user-driven recovery: detect orphan (`running` tool + no matching `QuestionRequest`), show interrupted banner, and recover via explicit endpoint that fails stale tool and re-presents or resumes planning.

## Context / Findings
- Question pending is memory-only: `packages/core/src/question.ts:79` (`Map`), `packages/opencode/src/question/index.ts:68-85` (`InstanceState Map` + fail-all finalizer). `Asked/Replied` not durable: `packages/schema/src/question.ts:70-86`, absent from `packages/schema/src/durable-event-manifest.ts`, gated in `packages/core/src/event.ts:369-396`.
- After restart `question.list` = `[]`, bootstrap `packages/app/src/context/global-sync/bootstrap.ts:480-515` clears dock; no buttons.
- Tool part durable `running`: `packages/core/src/session/message-updater.ts:271-287`, `packages/core/src/session/projector.ts:379-389`. Shimmer via `BasicTool pending` (`packages/session-ui`), detected in `packages/app/src/pages/session/use-plan-info.ts:13-25`.
- Buttons require matching `QuestionRequest.tool.callID/messageID`: `use-plan-info.ts:66-76`, `session-composer-region.tsx:40-58`, `session-plan-question-dock.tsx:47-81`.
- Runner only heals on active run: `packages/core/src/session/runner/llm.ts:390-398` (`hasSteer/hasQueue/force` guard before `failInterruptedTools:119-139`). Idle restart never heals per `specs/v2/session.md:160-167` (post-crash recovery deferred, `wake` must not infer).
- Plan tab empty vs exists: `packages/app/src/components/session/session-plan-tab.tsx:422-429`, `packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts:108-122` (`planCycleAnchor` + `resolvePlanFile`).
- V1 cleanup precedent: `packages/opencode/src/session/processor.ts:553-611` marks `error+interrupted:true`, ignored in `prompt.ts:96-100,1106-1129`.

## Approach
Chosen: on-demand UI-driven explicit recovery (spec-compliant, minimal). No auto-fail on boot, no durable questions. Detect orphan client-side, show `Session interrupted` banner with Resume / Re-present / Discard. User gesture calls new explicit `POST plan/recover` which fails stale part (`error+interrupted:true` V1, `Tool.Failed` V2 via explicit `resume(force=true)`), then re-asks same `present_plan` question if file exists, else admits synthetic resume message, or does nothing on discard. Reuses existing `Session.plan/resolvePlanFile`, `tool/plan.ts:54-70` payload, and `failInterruptedTools` paths.

## Files affected
- `packages/opencode/src/session/session.ts` — add `recoverInterruptedPlan` (find stale `present_plan running`, mark `error/interrupted:true`, resolve plan file, branch re-present/resume/discard; extract accept→build-switch helper shared with `tool/plan.ts`).
- `packages/opencode/src/server/routes/instance/httpapi/groups/session.ts` + `handlers/session.ts` — add `POST /api/session/:sessionID/plan/recover`, error mapping (404 unknown, 409 when working).
- `packages/opencode/src/tool/plan.ts` — extract shared question payload + accept helper, no live-path behavior change.
- `packages/app/src/pages/session/use-plan-info.ts` — add `orphaned` memo (`pendingTool && planInfo loaded && !pendingRequest`).
- `packages/app/src/pages/session/composer/session-plan-question-dock.tsx` + new `session-interrupted-dock.tsx` — orphan banner (Review/Resume/Discard), wired via `useMutation` to new endpoint; keep existing dock for non-orphan.
- `packages/app/src/pages/session/composer/session-composer-state.ts` — ensure `orphaned` stays non-blocking for composer input.
- `packages/core/src/session/runner/llm.ts` — expose explicit recover via existing `resume(force=true)` → `failInterruptedTools`; no guard change, no `wake` inference.
- i18n keys (`packages/app/src/i18n/en.ts`, `packages/ui/src/i18n/en.ts`) — banner/buttons, no hardcoded copy.

## Step-by-step implementation
1. `use-plan-info.ts`: add `orphaned` memo + return it; guard on `planInfo` resolved to avoid flash.
2. New `session-interrupted-dock.tsx`: props `{ sessionID, path?, exists, callID }`, buttons matrix (exists ? Review/Re-present/Resume/Discard : Resume-planning/Discard), `useMutation` to `plan/recover`, toasts on error.
3. Wire dock in `session-composer-region.tsx`: if `orphaned` show interrupted dock, else existing `SessionPlanQuestionDock` / `SessionQuestionDock`.
4. Hide orphan UI when session actively working (`SessionStatus`); server returns 409 if working.
5. `session.ts:recoverInterruptedPlan`: require session → `anchor=planCycleAnchor ?? info` → `expected=plan(anchor)` → `path=resolvePlanFile` → `exists=existsSafe`; find last `present_plan running` part; mark `error: Tool execution interrupted, metadata.interrupted:true` (mirror `processor.ts:597-606`); idempotent if already error.
6. Branch: `exists && re-present` → `Question.ask` same 4-option payload as `tool/plan.ts:54-70` with `tool:{messageID,callID}` of failed part; `!exists || resume` → synthetic user message `Continue planning...` + wake; `discard` → stop after fail.
7. Add `plan/recover` endpoint (groups + handlers), return `{path, exists, action}`.
8. Refactor `tool/plan.ts` to share payload/helper with recover.
9. V2 parity: handler calls `SessionExecution.resume` (force) when V2-placed so `failInterruptedTools` publishes `Tool.Failed` preserving `provider.metadata`.
10. i18n + `blocked` non-gating + per-callID guards (`activatedPlanCallIDs`, `openedForPresentPlan`) reuse.

## Risks / edge cases
- `present_plan` vs `plan_enter` payloads differ — map tool name to correct re-ask text.
- `resolvePlanFile` fallback (newest `*-slug.md` since anchor) must be reused to avoid false `No plan yet`.
- Double-click / double-tab: idempotent handler — check `question.list` before second `ask`, no-op if already `error+interrupted`.
- Child sessions: scope to owning session ID only, don't match child `QuestionRequest` (see `session-request-tree.ts` tree walk).
- Concurrent drain: hide banner when working, 409 on server.
- Discard must not delete plan file.
- V1 `error` vs V2 `Tool.Failed` must both project to non-pending so shimmer clears (`message-updater.ts:320-342`).

## Testing strategy
- Unit V1 `recoverInterruptedPlan`: file-exists → stale→`error/interrupted` + new `QuestionRequest` matching callID; no-file → synthetic resume, no question; discard → only fail; idempotent second call.
- Unit V2: explicit `resume(force)` marks `running→Failed`, preserves metadata, leaves `completed` untouched.
- Contract: `{path,exists,action}`, 404/409 cases.
- UI Solid tests: `orphaned` true only when `pendingTool && !pendingRequest && loaded`; banner matrix.
- Manual E2E: kill server mid-shimmer → restart → banner not infinite shimmer → Re-present restores 4-option dock; delete-file variant → Resume planning; Discard → idle + composer usable. Run `bun typecheck` from package dirs, backend `:4096` + app `:4444` per `AGENTS.md`.
- Existing suites: `packages/opencode/test/question/*`, `packages/core/test/session-runner.test.ts`, plan-tab bootstrap tests.
