# MCP Logos for Built-in Servers

## Summary
Add brand logos next to the three inbuilt MCPs (`linear`, `github`, `notion`) via a new hand-managed `mcp-icons` sprite in `packages/ui` and render it in the two MCP list UIs in `packages/app`. No backend/schema/protocol change — resolved by name on the frontend.

## Context / Findings
- Builtins defined in `packages/opencode/src/config/config.ts:50-69` (`linear`, `github`, `notion` remote entries, `enabled:false`). Schema `packages/core/src/v1/config/mcp.ts:6-63` has only `type,url,headers,oauth,enabled,timeout` — no icon field. Status API `packages/opencode/src/mcp/index.ts:83-107` + `server/routes/instance/httpapi/groups/mcp.ts` returns only `Record<string, Status>`.
- Two render points in `packages/app`: `components/dialog-select-mcp.tsx:64-67` (row: name + statusLabel + Switch) and `components/status-popover-body.tsx:414-436` (row: status dot + name + Switch). Both have no icon slot. Generic `icon="mcp"` only in `packages/session-ui/.../basic-tool.tsx:333` and `message-part.tsx:598` (out of scope).
- Canonical icons live in `packages/ui/src/assets/icons/provider|app|file-types/`, built by `vite-plugin-icons-spritesheet` in `packages/ui/vite.config.ts:10-24` into `sprite.svg + types.ts`, consumed via `components/provider-icon.tsx` (`<ProviderIcon id>` with `synthetic` fallback). `assets/icons/provider/` is auto-overwritten by `fetchProviderIcons()` (`vite.config.ts:47-58`) — must NOT put MCP logos there.

## Approach
Convention-by-name, no schema change. Add `assets/icons/mcp/{linear,github,notion}.svg`, add a third `iconsSpritesheet` entry outputting `src/components/mcp-icons/`, add a new `McpIcon` component mirroring `ProviderIcon` (returns null for unknown IDs), and insert it into the two MCP rows. This avoids protocol regen (`bun run generate`), versioning, and backfill, and survives provider-icon clobbering.

## Files affected
- `packages/ui/src/assets/icons/mcp/{linear,github,notion}.svg` — new, 24x24 `currentColor` SVGs (new hand-managed folder)
- `packages/ui/vite.config.ts` — add third `iconsSpritesheet` entry `{ inputDir: src/assets/icons/mcp, outputDir: src/components/mcp-icons }`
- `packages/ui/src/components/mcp-icons/sprite.svg` + `types.ts` — generated on build, commit like provider-icons
- `packages/ui/src/components/mcp-icon.tsx` (new) — mirror `provider-icon.tsx`, fallback to `null`
- `packages/ui/src/components/mcp-icon.stories.tsx` (new) — mirror `provider-icon.stories.tsx`
- `packages/ui/package.json` — add sprite to `files`, add `./icons/mcp` export (mirror provider entries)
- `packages/app/src/components/dialog-select-mcp.tsx:64-67` — insert `<McpIcon id={i.name} class="size-4 shrink-0" />` before name
- `packages/app/src/components/status-popover-body.tsx:433-436` — insert `<McpIcon>` next to name, keep status dot as health indicator

## Step-by-step implementation
1. Add 3 SVGs to `packages/ui/src/assets/icons/mcp/` (monochrome, `currentColor`, no embedded styles).
2. Add `mcp` entry to `iconsSpritesheet` in `packages/ui/vite.config.ts`; run UI dev/build once to emit `src/components/mcp-icons/sprite.svg + types.ts`; update `package.json` files/exports.
3. Create `packages/ui/src/components/mcp-icon.tsx` (props `{ id }`, `iconNames.includes(normalizedId)` check, `null` fallback) + stories; export from barrel.
4. Update `dialog-select-mcp.tsx` row: `[McpIcon?] name statusLabel` — hide icon when ID unknown.
5. Update `status-popover-body.tsx` MCP row: `[dot] [McpIcon?] name` — keep dot, add `size-4 shrink-0` logo.
6. Run `bun typecheck` in `packages/ui` and `packages/app`; visual check light/dark.

## Risks / edge cases
- Sprite name collision with provider sprite — mitigated by separate `mcp-icons/` dir + `data-component="mcp-icon"`.
- Renamed/custom MCP (`my-linear`) shows no logo by design (exact lowercased match); degrades to current text UI.
- Dark mode contrast — verify `currentColor` SVGs on both themes; Notion/Linear black marks need stroke/fill check.
- Brand license — use official Simple Icons / vendored provider-style marks.
- TUI/CLI (`packages/opencode/src/cli/cmd/mcp.ts`) unchanged — no image support there.

## Testing strategy
- `bun typecheck` in `packages/ui`, `packages/app`.
- Storybook/visual for `McpIcon`: 3 IDs render, unknown ID renders nothing.
- Manual: enable builtin (`"mcp": {"linear": {"enabled": true}}`), open MCP dialog + status popover MCP tab; confirm logo + name + Switch layout, light/dark, long custom names truncate, custom MCP shows no broken image.
- Confirm provider `fetchProviderIcons()` run does not clobber `mcp/` assets.
