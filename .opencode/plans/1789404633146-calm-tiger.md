# Rendered Plan Markdown + Auto-Activate Plan Tab

## Summary
Render `SessionPlanTab` as markdown (not raw `plan.md` source) while keeping source-line-anchored selection/commenting; fix first-create `present_plan` flow so review pane auto-activates the Plan tab instead of staying on Files Changed.

## Context / Findings
- Plan window = `packages/app/src/components/session/session-plan-tab.tsx:46 SessionPlanTab`, rendered in `session-side-panel.tsx` `plan` tab via `use-plan-info.ts` (`present_plan running` + `client.session.plan` + `file.load`).
- Today renders raw via Pierre `File mode="text"` (`session-plan-tab.tsx:229-259`) -> `TextViewer`/`VirtualizedFile` (`session-ui/src/components/file.tsx`), with `#, **, ``` ` visible.
- Selection/commenting is source-line addressed: `SelectedLineRange {start,end}` (`app/src/context/file/types.ts`), `createLineCommentControllerV2` (`session-ui/src/v2/components/line-comment-annotations-v2.tsx`), `comments.add/list` (`app/src/context/comments.tsx`), `prompt.context.add/updateComment` + `previewSelectedLines` (`selection-bridge.ts`) + `triggerRevise()` answering `present_plan` with Revise.
- DOM anchoring relies on Pierre ShadowDOM `[data-line]` (`pierre/file-selection.ts`, `commented-lines.ts`, `comment-hover.ts`).
- Markdown precedent = `session-ui/src/components/markdown.tsx` (worker `marked + marked-shiki + katex`, sanitize, morphdom) — has NO `data-line`/selection/commenting. No `mode="markdown"` exists.
- Review pane = `pages/session/session-side-panel.tsx` (`Tabs value={activeTab()}`), state in `context/layout.tsx` + `layout-tabs.ts` + `pages/session/helpers.ts:createSessionTabs`. `plan` behaves like `context` (in `all`, closable), `review` never persisted.
- `activeTab` fallback chain (`helpers.ts:66-79`) has NO `plan` branch -> misses resolve to file/context/review/empty, never plan.
- Canonical first-create opener `pages/session.tsx:412-429` does `reviewPanel.open() + open("plan") + setActive("plan")` guarded by per-mount `openedForPresentPlan:Set<callID>` — lost on remount, races persisted restore, fragile `void open(); setActive();`.
- `session-plan-indicator.tsx:14-17` does `open("plan")` WITHOUT `setActive` — visible tab appears but selection stays on review.
- User decisions: block-maps-to-lines granularity; always-steal auto-activate on new plan.

## Approach
Chosen: A1 rendered-first with `data-source-line` mapping, reuse line-comment controller; B always-steal reactive auto-activate.

For rendering: extend markdown worker projection to emit per-block `{startLine,endLine}` (1-indexed in exact `contents()` string), write as `data-source-start/end` on `div[data-markdown-block]` in `markdown.tsx`, add light-DOM `markdown-selection.ts` translating Selection/gutter-click to `SelectedLineRange{start,end,side:"additions"}`, reuse `createLineCommentControllerV2`, `comments` + `prompt.context` + `triggerRevise` unchanged. Raw `previewSelectedLines` still slices `contents().split("\n")` so LLM context stays exact. Gutter v1 = per-block hover `+` rail aligned via `offsetTop` + `ResizeObserver` (no Pierre line-number column). Focus scroll repointed to `querySelector` intersecting block + `scrollIntoView`.

For auto-activate: extract shared `ensurePlanActive()` (`openReviewPanel + open("plan") + setActive("plan")`), fix indicator to call it, add reactive `createEffect(on(plan.pending))` in side-panel/session that always steals to `plan` on `false->true` per-`callID`, harden `session.tsx` with `batch`/`queueMicrotask` + re-assert while pending. No fallback-chain change needed if always-steal (explicit active covers it); keep guard so explicit `close("plan")` is respected until next `callID`.

Why: preserves single commenting path and storage model, avoids side-by-side width cost and dual-mode drift; reactive pending-signal fixes timing/early-fire root cause rather than patching each opener.

## Risks / edge cases
- Tables/fences/lists = 1 block ↔ N lines: whole-block highlight for single-line comment is acceptable v1; keep drag endpoints precise, expand only for gutter-click.
- Line drift on `file.load(force:true)` reload/streaming: snapshot `sampledChecksum(contents())` with draft; clamp/mark-stale, never silently re-anchor.
- CRLF/trailing-newline/`marked` normalization/sanitizer stripping HTML comments skewing counts — count on exact string passed to both renderer and preview.
- ShadowDOM→light-DOM: update selectors from `[data-line]` to `[data-source-start]`; do not run `markCommentedFileLines` on markdown root.
- Long plans: debounce re-parse, preserve `completedCode` cache; avoid resetting selection on appends below selection.
- Always-steal can yank user off file they just opened — accepted per user choice; mitigate by only stealing on `pending false->true` transition per `callID`, not on every `planKey` refetch.
- Per `packages/app/AGENTS.md`: record session/timeline benchmark baseline before `markdown.tsx` worker changes, compare after; use `language.t` for all new copy; `bun typecheck` from package dir, never `tsc`.
