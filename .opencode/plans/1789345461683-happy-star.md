# Soften Restart-Interrupted Question Display

## Summary
Render question tool parts interrupted by a restart as a neutral timeline status instead of the red generic Failed card. Preserve the existing soft dismissal treatment and keep genuine question transport failures visible as errors.

## Context / Findings
- `packages/session-ui/src/components/message-part.tsx` classifies failed tool parts; it already softens canonical question dismissal errors.
- Restart/recovery emits `Tool execution interrupted` for question tool parts, which currently falls through to `ToolErrorCard` and its red Failed presentation.
- `packages/session-ui/src/components/tool-error-card.tsx` is generic and should not be changed for this question-specific case.
- Existing `ui.messagePart.questions.dismissed` copy should remain for intentional dismissal; the requested wording is a distinct neutral `Question interrupted` status.
- Existing E2E coverage distinguishes softened question dismissal from genuine `Question transport failed` errors.

## Approach
Extend the question-specific error classifier with an exact match for `Tool execution interrupted`, rendering a new localized static status. Keep all other question errors, including transport failures, on the existing error-card path. Use exact normalized protocol messages rather than broad substring matching so real failures are not hidden.

## Files affected
- `packages/session-ui/src/components/message-part.tsx` — classify restart-interrupted question errors and render the localized neutral status.
- `packages/ui/src/i18n/en.ts` — add the `Question interrupted` source translation key.
- `packages/ui/src/i18n/*.ts` — add the new key through the existing locale parity workflow/fallback pattern.
- `packages/app/e2e/regression/session-timeline-tool-projection.spec.ts` — cover interrupted questions, intentional dismissal, and preserved transport failures.

## Step-by-step implementation
1. Normalize the question tool error by removing the leading `Error:` prefix and trimming whitespace.
2. Match only the canonical dismissal message and exact `Tool execution interrupted` message in the question-specific branch.
3. Continue rendering the existing localized `Questions dismissed` text for intentional rejection; render the new localized `Question interrupted` text for restart interruption.
4. Leave non-question tool errors and other question errors on `ToolErrorCard` unchanged.
5. Extend focused timeline projection tests to assert the neutral interruption status, no error card for it, and continued error-card rendering for `Question transport failed`.
6. Run the affected app/session-ui typecheck or focused test commands from package directories, not the repository root.

## Risks / edge cases
- Avoid substring matching that could misclassify a real transport failure mentioning dismissal or interruption.
- Do not reuse dismissal copy for restart recovery because it falsely implies user action.
- Keep the interruption status static and non-interactive; do not announce historical recovery as an urgent alert.
- Locale dictionaries must remain key-parity compliant.

## Testing strategy
- Assert canonical question dismissal remains softened.
- Assert a question with `Tool execution interrupted` shows `Question interrupted` and no `data-kind="tool-error-card"`.
- Assert `Question transport failed` still shows the generic error card and original detail.
- Run the focused E2E regression and relevant package typechecks.
