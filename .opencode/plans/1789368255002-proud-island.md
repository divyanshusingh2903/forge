# Forge-mark shimmer + blocked skeletons on startup load

## Summary
On cold start the sidebar, session list, new-session page, and session detail paint blank-but-clickable while data loads. Add a shared forge-mark shimmer loader + placeholder blocks, and block clicks (inert / pointer-events-none / disabled + aria-busy) until each surface is ready.

## Context / Findings
- New shell: `packages/app/src/pages/layout-new.tsx` — `HomeProjects` sidebar + `<main><Suspense>{children}</Suspense></main>` with no fallback.
- Legacy shell: `packages/app/src/pages/layout.tsx`, `pages/layout/sidebar-shell.tsx` (rail `For each=projects()` no fallback), `sidebar-workspace.tsx` (only `WorkspaceSessionList` has `SessionSkeleton` + `busy() -> opacity-50 pointer-events-none`), `sidebar-items.tsx:326` (`SessionSkeleton` = `h-8 animate-pulse bg-surface-raised-base`).
- Home list: `home-sessions-controller.tsx:173` exposes `data.loading = sessionLoad.isLoading` but `home-sessions.tsx` drops it; `home-sessions-view.tsx:115` shows `HomeSessionsEmpty` when `groups()==[]`, so first paint is clickable Empty. `HomeSessionSkeleton:539` exists but static (no pulse) and only as `Suspense` fallback.
- Detail: `pages/session.tsx` renders header + composer while `timeline.ready==false`; `TargetSessionRoute Show when={directory()}` (`session.tsx:273`) has no fallback — blank workspace, shell still clickable.
- New session: `new-session/new-session-view.tsx:44` renders composer immediately; draft `readyPromise` resource never suspends UI.
- Assets: forge mark = `Mark`/`Splash` in `packages/ui/src/components/logo.tsx` (code-drawn SVG, `data-component="logo-mark/splash"`). Shimmer precedent = `TextShimmer` (`packages/ui/src/components/text-shimmer.tsx/css`, v2 variant) with char-sweep + `prefers-reduced-motion` guard. Spinners = `Spinner`, `LoaderV2`. Veil precedent = `dialog-edit-project-v2.tsx:69` (`absolute inset-0 ... backdrop-blur + Spinner`). Disabled precedent = `button-v2.css` (`:disabled -> opacity + cursor-not-allowed`).
- Conventions: `data-component`/`data-slot` selectors, per-component CSS imported in `styles/index.css` under `layer(components)`, copy via `language.t("common.loading")` (never hardcode), Solid `Show`/`Suspense` + `inert` for click-blocking.

## Approach
Create one reusable loading primitive in `packages/ui` (forge mark + shimmer wrapper + pulse blocks + veil), never editing `logo.tsx` rect fills. Wire it as the explicit loading branch in each of the three surfaces, driven by the existing loaders (`sessionLoad.isLoading`, `directory()`, `timeline.ready`, draft `readyPromise` / providers), and block interaction on the loading subtree only (content region, not titlebar/nav) so back-nav, Settings/Help stay reachable.

## Files affected
- `packages/ui/src/components/loading-state.tsx` (new) — `ForgeMarkLoader`, `LoadingBlock`, `SessionLoadingState`, `LoadingVeil`.
- `packages/ui/src/components/loading-state.css` (new) — shimmer keyframes, block + veil styles, reduced-motion guard.
- `packages/ui/src/styles/index.css` — import new CSS in `layer(components)`.
- `packages/app/src/pages/home/home-sessions.tsx` — pass through `loading`.
- `packages/app/src/pages/home/home-sessions-view.tsx` — gate list on `loading`, upgrade `HomeSessionSkeleton` (add `animate-pulse`/`aria-hidden`) or swap to shared state.
- `packages/app/src/pages/home/home-projects-view.tsx` (+ `home-projects-controller.tsx` if needed) — sidebar loading branch + `aria-busy`/`inert` on content.
- `packages/app/src/pages/layout-new.tsx` — explicit `Suspense` fallback for `main`.
- `packages/app/src/pages/session.tsx` — `Show when={directory()}` fallback + timeline-ready gate + composer `ready`/disabled.
- `packages/app/src/pages/new-session/new-session-view.tsx` (+ draft/workspace controllers) — accept `loading` prop, skeleton branch, disable composer controls.
- Legacy (only if still supported): `packages/app/src/pages/layout/sidebar-shell.tsx`, `sidebar-workspace.tsx`, `pages/layout.tsx` — rail `fallback`, panel `project()===undefined` skeleton, same click-block.

## Step-by-step implementation
1. UI primitive: add `loading-state.tsx` rendering existing `Mark` inside `<div data-component="forge-loading">` + `LoadingBlock` rows + `SessionLoadingState` composite (`role="status" aria-live="polite"`, blocks `aria-hidden`). No changes to `logo.tsx`.
2. CSS: add `loading-state.css` — gradient sweep on wrapper (not SVG rects), `animate-pulse` blocks using `var(--v2-*)` tokens (legacy variant `bg-surface-raised-base`), veil `absolute inset-0 z-10 bg-*/60 backdrop-blur`, `prefers-reduced-motion: reduce -> animation none`.
3. Sidebar (new layout): derive `loading` (servers empty / health unresolved / projects unready); `<Show when={loading()} fallback={real list}>` skeleton in `HomeProjectsView`; `aside` gets `aria-busy + inert + pointer-events-none select-none` on content only.
4. Home list: plumb `sessions.data.loading` into `HomeSessionsView` as `loading` prop; change `Show when={groups().length>0}` to `Show when={!loading()}` outer with skeleton fallback, inner empty-vs-groups as today; combine `isLoading || (isFetching && groups().length===0)` so cached refetches don't flash.
5. Session detail: add `fallback={<SessionLoadingState/>}` to `Show when={directory()}`; gate timeline region on `messagesReady()` (only when `params.id` set); composer gets `aria-busy`/`inert`/`pointer-events-none` + disabled controls until ready.
6. New session: accept `loading` (draft `readyPromise` pending || providers/directory not ready); `Show` skeleton vs composer; disable `PromptWorkspaceSelector`/`PromptProjectAddButton` while loading.
7. Layout fallback: give `<Suspense>` in `layout-new.tsx:88` an explicit `<SessionLoadingState/>` fallback; add ~150ms show-delay so fast loads don't flash.
8. Legacy parity (if in scope): rail `For fallback`, panel undefined-project skeleton, same `busy()` pattern already in `sidebar-workspace.tsx`.

## Risks / edge cases
- Over-blocking nav if `inert` covers sidebar chrome — block content region only, keep Titlebar/Settings/Help enabled.
- Skeleton flash on fast/cached loads — delay veil ~150-200ms; only veil initial load (`groups().length===0`), not refetch.
- Two shells diverging — patch both `layout-new` and legacy sidebar or one stays broken.
- False-ready (`isLoading false` on cache, `timeline.ready true` when `!id`) — scope veil to initial-load + `params.id` set.
- Logo regression — shimmer on wrapper only, never touch `logo.tsx`/`logo.css` fills.

## Testing strategy
- Manual (per `packages/app/AGENTS.md`: backend `bun run ./src/index.ts serve --port 4096` from `packages/opencode`, app `bun dev -- --port 4444` from `packages/app`, open `localhost:4444`): cold start + throttled network → each surface shows centered forge mark + blocks; clicks no-op; reduced-motion → static.
- Unit: `isTimelineReady` / `groupSessions` empty-vs-loading branch; loader sets `aria-busy`/`inert`, blocks `aria-hidden`.
- E2E via `agent-browser`: snapshot during load, assert veil present + rows/composer non-clickable, absent after load.
- `bun typecheck` from `packages/app` (never `tsc` directly).
