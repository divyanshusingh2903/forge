# Soften Restart-Interrupted Question Display

## Summary
Replace the alarming red `Failed` presentation shown when a restart interrupts a question-backed tool (`question`, `present_plan`, or `plan_enter`) with a neutral, localized `Interrupted` card. The card will still identify the tool, remain expandable, preserve the original interruption diagnostic, and retain the copy action so this is only a presentation change. Existing user dismissal behavior, ordinary tool failures, and all backend/session semantics remain unchanged.

## Context / Findings
- `packages/session-ui/src/components/message-part.tsx` routes tool error parts to `ToolErrorCard`; only the existing `question` dismissal message is special-cased.
- Restart recovery persists interrupted tool calls as error states with interruption text, so they currently fall through to the red error card.
- `packages/session-ui/src/components/tool-error-card.tsx` hardcodes the card variant to `error` and derives the fallback subtitle as localized `Failed`.
- `packages/ui/src/i18n/en.ts` and other locales already provide `ui.message.interrupted`.
- `present_plan` and `plan_enter` are question-backed tools and should receive the same presentation treatment; ordinary errors and unrelated tool interruptions must remain red failures.
- Existing Storybook coverage includes ordinary tool errors and dismissed questions, but not restart interruption rendering.

## Approach
Add a narrowly scoped interrupted presentation mode to `ToolErrorCard`. Detect only the canonical interrupted error state for `question`, `present_plan`, and `plan_enter` at the message-part rendering boundary, then pass the mode through so the card uses a neutral/info treatment and the existing localized `ui.message.interrupted` label while retaining the original error body and copy affordance. Keep dismissal precedence and avoid changing persisted state or protocol behavior.

## Files affected
- `packages/session-ui/src/components/message-part.tsx` — identify eligible restart-interrupted question-backed tool errors and pass the interrupted presentation state.
- `packages/session-ui/src/components/tool-error-card.tsx` — support the interrupted state, localized summary, neutral variant, and appropriate non-error icon while preserving diagnostics.
- `packages/session-ui/src/components/tool-error-card.css` — adjust any interrupted-state selection/accent styling if needed so the expanded content is not presented with danger colors.
- `packages/session-ui/src/components/tool-error-card.stories.tsx` — add representative interrupted and ordinary-error examples for visual regression/manual review.

## Step-by-step implementation
1. Define a narrow interruption predicate based on the stable persisted interruption marker/text and limit it to `question`, `present_plan`, and `plan_enter`.
2. Preserve the current dismissed-question branch before interruption handling.
3. Add an explicit `interrupted` prop or status to `ToolErrorCard`; use `Card`’s neutral/info-compatible presentation, the localized `ui.message.interrupted` subtitle, and a non-error status icon without removing expand/copy behavior.
4. Keep raw error text available in the expanded body and ensure normal errors, unrelated tools, pending/running parts, and dismissed questions retain their current behavior.
5. Extend the Storybook samples to cover a restart-interrupted question-backed tool plus a normal error and verify the visual distinction.

## Risks / edge cases
- Do not classify arbitrary errors containing broad words like “restart” or “interrupt”; match the canonical interruption marker.
- Preserve dismissal precedence if a dismissal payload is present.
- Avoid implying successful completion: interrupted should be neutral/status information, not success.
- Keep localization through existing typed i18n keys; do not add hardcoded English UI text.

## Testing strategy
- Run the session-ui package typecheck/lint or its targeted test command after implementation.
- Review the Storybook interrupted and normal-error states to confirm neutral versus red treatment.
- Verify the expanded interrupted card still exposes the original diagnostic and copy action.
- Run the relevant existing session-ui/component tests if available.
