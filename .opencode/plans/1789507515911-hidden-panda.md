# MCP Logos for Inbuilt Servers (linear, github, notion)

## Summary
Add brand logos next to the three inbuilt MCPs (linear, github, notion) in the app UI, following the existing ProviderIcon sprite pattern but as a separate MCP sprite. Frontend-only name-to-logo map with generic mcp glyph fallback for custom servers - no config schema or API change.

## Context / Findings
- Inbuilt MCPs defined in one place: `packages/opencode/src/config/config.ts:46-69` as `builtinMcp` record (linear, github, notion, all type remote, enabled false). Seeded then re-asserted after merges so user config cannot delete them.
- Schema has no logo field: `packages/core/src/v1/config/mcp.ts` (Local/Remote) and V2 `packages/core/src/config/mcp.ts` - adding one would touch config, protocol, sync payload.
- UI surfaces showing MCPs (all currently logo-less):
  - `packages/app/src/components/status-popover-body.tsx:400-467` - MCP tab, primary surface: status dot + name + Switch, no icon.
  - `packages/app/src/components/dialog-select-mcp.tsx:63-87` - manage dialog: name + status label + Switch, no icon.
  - `packages/session-ui/src/components/message-part.tsx:499-602` + `basic-tool.tsx:323` - MCP tool calls always render generic Icon name=mcp (`packages/ui/src/components/icon.tsx:52`).
  - `packages/app/src/components/prompt-input/slash-popover.tsx` - MCP badge is text Tag, @ resources use generic FileIcon; TUI/CLI (`packages/opencode/src/cli/cmd/mcp.ts`) is text-only.
- Logo pattern to copy: `packages/ui/src/assets/icons/provider/*.svg` + vite-plugin-icons-spritesheet in `packages/ui/vite.config.ts:10-24` generating `src/components/provider-icons/{sprite.svg,types.ts}`, rendered by `packages/ui/src/components/provider-icon.tsx` with synthetic fallback. Verified: provider/ dir is network-synced by fetchProviderIcons() (overwrites on dev/build), so MCP SVGs must NOT go there. Separate file-icons/, app-icons/ sprites are the precedent for a new domain.

## Approach
Frontend-only McpIcon component backed by a new `src/assets/icons/mcp/` sprite (linear.svg, github.svg, notion.svg). Insert it in the two MCP management surfaces (status popover + select dialog). Custom/unknown MCP names fall back to the existing generic mcp glyph. No backend, schema, TUI, or tool-rendering changes in v1 - keeps the change to ~3 SVGs + 1 component + 2 call-site edits.

## Files affected
- `packages/ui/src/assets/icons/mcp/{linear,github,notion}.svg` - NEW: brand SVGs, normalized to viewBox 0 0 24 24 (from simple-icons / official press kits).
- `packages/ui/vite.config.ts` - add third iconsSpritesheet entry: inputDir src/assets/icons/mcp, outputDir src/components/mcp-icons.
- `packages/ui/package.json` - publish src/components/mcp-icons/sprite.svg, add ./icons/mcp export (mirror provider entry).
- `packages/ui/src/components/mcp-icons/{sprite.svg,types.ts}` - GENERATED via bun dev/build in packages/ui, commit both.
- `packages/ui/src/components/mcp-icon.tsx` (+ mcp-icon.stories.tsx) - NEW: clone of provider-icon.tsx, case-insensitive name lookup, fallback to Icon name=mcp.
- `packages/app/src/components/status-popover-body.tsx` - insert McpIcon before status dot in MCP tab row (~L423).
- `packages/app/src/components/dialog-select-mcp.tsx` - insert McpIcon before name span (~L67).

## Step-by-step implementation
1. Add 3 SVGs under `packages/ui/src/assets/icons/mcp/` (linear, github, notion).
2. Register sprite in `packages/ui/vite.config.ts`; update `packages/ui/package.json` publishes/exports.
3. Run build/dev in `packages/ui` to regen `src/components/mcp-icons/sprite.svg` + `types.ts`; commit generated files.
4. Create `mcp-icon.tsx` (name -> sprite use, else generic Icon name=mcp fallback) + stories; handle 16px sizing, rounded-[4px], dark/light contrast.
5. Edit `status-popover-body.tsx` MCP row: [logo] [dot] [name] [switch].
6. Edit `dialog-select-mcp.tsx` row: [logo] [name + status] [switch].
7. Typecheck (bun typecheck in packages/ui, packages/app); visual check with one builtin enabled + one custom MCP confirming fallback.

## Risks / edge cases
- Brand SVG licensing/attribution - use official/simple-icons sources, keep fill colors readable in dark + light mode.
- fetchProviderIcons() overwrites provider/ on every build - mitigated by using separate mcp/ dir.
- Case mismatch (Linear vs linear) - normalize lookup with toLowerCase().
- MCP tool-call surfaces (message-part.tsx, basic-tool.tsx) still show generic icon - intentional v1 scope cut; tool id alone does not carry server name without prefix parsing.
- Slash popover Tag + TUI/CLI intentionally left text-only for consistency.

## Testing strategy
- bun typecheck in packages/ui and packages/app.
- Manual: backend bun run ./src/index.ts serve in packages/opencode + bun dev in packages/app; enable one builtin via mcp: { linear: { enabled: true } }, verify logo in status popover MCP tab and MCP dialog; add dummy custom MCP and verify generic mcp fallback renders.
- Dark/light mode contrast check for the three logos.
