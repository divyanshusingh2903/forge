# Align the persistent projects sidebar with the main panel

## Context

The new layout mounts `HomeProjects` as a persistent sibling of `<main>` in `packages/app/src/pages/layout-new.tsx` (`NewLayout`, lines 81-94). `HomeProjectsView` currently gives its root `<aside>` `h-full`, filling the complete space below the titlebar (`packages/app/src/pages/home/home-projects-view.tsx`, lines 93-98).

On the home route, the visible main surface is `NewHome`'s rounded card, which has `m-2` (`packages/app/src/pages/home.tsx`, lines 20-25). This leaves the main card inset by 8px on every edge while the sidebar reaches the row boundary. The screenshot reflects that mismatch: the sidebar begins higher and ends lower than the main content surface.

The user confirmed the intended result is a sidebar inset on every edge that matches the main panel.

## Design decisions

Apply the 8px inset locally to the persistent projects/sidebar component rather than relocating the main card margin into `NewLayout`. This keeps the existing main-route framing unchanged, gives the sidebar the same visual bounds, and avoids changing all routes rendered by the shared layout.

Preserve the sidebar's current fixed width, internal scroll ownership, and rounded right-side corners. The outer inset changes only its position and available height; its `min-h-0` and the existing `ScrollView` continue to constrain long project/session lists.

Use a Playwright geometry assertion rather than a unit test because the regression is produced by flex sizing and CSS margins in the browser. Cover more than one viewport height to guard against the sidebar returning to viewport-row height after a resize.

## Changes

### `packages/app/src/pages/home/home-projects-view.tsx`

Update the `HomeProjectsView` root `<aside>` class list to use the same 8px outer inset as `NewHome`: create top, bottom, and left spacing while retaining its 260px visual width and its existing right border/corner styling. Ensure the sidebar remains height-constrained within the flex row, so its project/session list scrolls internally rather than expanding the shell.

### `packages/app/e2e/regression/...`

Add or extend the focused new-layout regression fixture with deterministic project/session data and `newLayoutDesigns: true`. At an `xl` viewport, locate the persistent projects sidebar and the rounded home main surface, then compare their `getBoundingClientRect()` top and bottom bounds within one pixel. Repeat the assertion after reducing and restoring viewport height to prove the sidebar remains aligned and does not outgrow the main panel.

Choose the existing regression suite location after verifying which fixture can render the home route with the new persistent sidebar; do not add a legacy-layout assertion because that would not exercise `HomeProjectsView`.

## Out of scope

- Changing the shared `NewLayout` padding or the home card's existing `m-2` frame.
- Altering sidebar width, project/session behavior, or the legacy sidebar layout.
- Electron-specific window-chrome testing; the desktop renderer consumes this shared app UI, and the regression targets the CSS layout itself.

## Verification

From `packages/app`, run the focused Playwright regression that contains the new geometry assertion:

```bash
bun run test:e2e -- e2e/regression/<sidebar-alignment-spec>.spec.ts
```

Run the relevant existing sidebar/resize regression suites if the selected file shares their fixture:

```bash
bun run test:e2e -- e2e/regression/file-browser-sidebar-tab-switch.spec.ts
bun run test:e2e -- e2e/regression/review-terminal-stacked.spec.ts
```

Manually verify the new home layout at desktop width with both short and long projects/session lists: the sidebar's top and bottom edges align with the rounded main card, the sidebar list scrolls internally, and vertical viewport resizing preserves the alignment.
