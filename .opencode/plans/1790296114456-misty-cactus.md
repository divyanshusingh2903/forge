# Show proposed file changes in permission prompts

## Context

Current V2 mutation tools ask for the shared `edit` permission before changing files, but their requests only include resource paths. `SessionPermissionDock` in `packages/app/src/pages/session/composer/session-permission-dock.tsx` renders the permission description, paths, and Allow/Deny actions without using `request.metadata`, so an approver cannot inspect the requested content.

`EditTool`, `WriteTool`, and `ApplyPatchTool` in `packages/core/src/tool/` intentionally avoid reading target contents until after permission is granted. The preview must therefore be constructed only from the already-supplied tool input and parsed patch hunks; it must not become a way to disclose current file contents after a denial. The app already preserves arbitrary request metadata and has reusable Pierre-backed file/diff rendering in `packages/session-ui/src/components/file.tsx` and `session-diff.ts`.

The requested scope is all file mutations: exact edits, writes, and apply-patch operations.

## Design decisions

- Define one browser-safe `Permission.FileChangePreview` schema in `packages/schema/src/permission.ts`, carried under the existing opaque `Request.metadata.preview` convention. The permission request contract remains backward-compatible for other metadata producers, while Core and App share an explicit preview shape rather than relying on unsafe casts.
- Represent each requested target as a file entry with its resource path, mutation status, and only the proposed before/after fragments available in the tool input. Exact edits show the requested replacement; writes show the proposed file contents; parsed patch additions and updates show their supplied lines, and deletes show the affected path/status. No tool will read disk contents before approval merely to improve this preview.
- Render an always-visible, scrollable per-file change preview inside the existing permission dock, using the established session-ui diff/file renderer where before/after content exists. Preserve the dock footer and keyboard approval shortcuts so inspecting the preview does not change accept/deny semantics.

## Changes

- `packages/schema/src/permission.ts`: add the serializable file-change preview schema and exported types used as the documented shape of `metadata.preview`; support multiple files and mutation status while retaining arbitrary metadata on permission requests.
- `packages/core/src/tool/edit.ts`: attach the resolved resource plus the supplied old/new replacement text as preview metadata on the `edit` permission assertion, before the protected file read.
- `packages/core/src/tool/write.ts`: attach the resolved resource and proposed write content as preview metadata on the `edit` permission assertion, without probing whether the file already exists.
- `packages/core/src/tool/apply-patch.ts`: convert validated parsed hunks into preview entries after target resolution and before the batched `edit` assertion. Include add/update content supplied in the patch and deletion status/path, preserving the single batched permission request.
- `packages/app/src/pages/session/composer/session-permission-dock.tsx`: safely decode `request.metadata.preview`, render preview entries above the decision controls, and leave unrelated permission types unchanged when metadata is absent or malformed.
- `packages/session-ui/src/components/message-part.css`: extend the permission-dock styles with a bounded, scrollable file-change preview that remains usable on short viewports without moving the approval controls out of view.
- `packages/core/test/tool-edit.test.ts`, `packages/core/test/tool-write.test.ts`, and `packages/core/test/tool-apply-patch.test.ts`: assert the emitted pending permission metadata for each mutation type and retain the invariant that no target file is read before approval.
- Add a focused app-side permission-preview test alongside the composer permission UI/state tests, covering valid edit/write/multi-file patch previews plus missing or malformed metadata falling back to the existing path-only prompt.
- Run `bun run generate` from `packages/client` after the public schema addition; do not edit generated client files directly.

## Out of scope

- Calculating a complete on-disk diff before permission approval, including deleted-file contents or the previous contents of writes. That would violate the current protected-read behavior.
- Changing permission rule evaluation, saved approvals, auto-response behavior, or the legacy tool permission UI.
