# Silent plan-file working in plan mode

## Summary
Stop permission prompts for internal plan working: `ls`/`cat`-style peeks at `.opencode/plans/` and read/edit/write of the active `*.md` plan file in `plan` agent should be auto-allowed as internal working, while everything else still prompts/denies as today and explicit user denies still win.

## Context / Findings
- Permission V1 flow: `packages/opencode/src/permission/index.ts` `evaluate()`/`ask()`; tools call via `packages/opencode/src/session/tools.ts` with `Permission.merge(agent.permission, session.permission)`.
- `bash` tool `packages/opencode/src/tool/shell.ts` `collect()`+`ask()`: file-touching args -> `external_directory` ask; every non-cd command -> `bash` ask with full command text + `BashArity.prefix + " *"`.
- `edit`/`write`/`apply_patch` use `permission:edit` with `path.relative(worktree, file)` patterns + `assertExternalDirectoryEffect` in `packages/opencode/src/tool/external-directory.ts`; `read` similar with `permission:read`.
- `plan` agent in `packages/opencode/src/agent/agent.ts:156-181` already allows `edit` on `.opencode/plans/*.md` + global `Global.Path.data/plans/*.md`, and `external_directory` on global plans dir. No `bash`/`read`/`glob`/`grep`/`list` exemption; VCS `.opencode/plans` needs no external_directory (inside worktree).
- Plan path: `packages/opencode/src/session/session.ts:332-337` `plan()` — VCS: `<worktree>/.opencode/plans/<ts>-<slug>.md`, else `<Global.Path.data>/plans/...`. Prompts (`plan-mode.txt:57`, `present-plan.txt:13`) forbid shell for plan writes but model still runs `ls`/`cat`/`head` which hit `bash` prompts.
- Existing internal bypass precedents: `session/prompt.ts:814-826` `execRead` with `ask:()=>Effect.void`, `tool/task.ts:119` `bypassAgentCheck`. Prefer declarative allowlist over code bypass so user denies still win.

## Approach
Extend the existing `plan`-agent declarative permission allowlist for path-scoped tools (`read`, `external_directory` for VCS plans dir), and add a narrow resolved-path filter in `shell.ts collect()` for read-only peeks whose every resolved arg is inside the plan dir. No broad `bash: allow`, no `*` bypass, user rules stay last in merge order so explicit deny still wins. Scope strictly to `plans/*.md` (plus the plans dir itself for `ls`), never `.opencode/*` broadly.

## Files affected
- `packages/opencode/src/agent/agent.ts` — extend `plan.permission` planSpecific block: add `read` allow for both plan locations, add `external_directory` allow for VCS `.opencode/plans/*`.
- `packages/opencode/src/tool/shell.ts` — in `collect()`, skip `dirs` entries and `patterns` adds only for read-only heads with all-resolved-args inside plan dir.
- `packages/opencode/src/tool/plan-path.ts` — NEW tiny helper `isPlanPath()` mirroring `Session.plan()` (VCS vs global, `contains` + `.md` check, dir itself counts).
- `packages/opencode/src/session/prompt/plan-mode.txt` — one-line wording touch: shell peeks on plans dir no longer prompt but write/edit remains required write path.
- `packages/core/src/plugin/agent.ts` — mirror V2 agent definition if plan permissions are duplicated there.
- `packages/opencode/test/agent/agent.test.ts` + new `shell collect` test — cover VCS/global allow + user-deny-wins + chained-command still prompts.

## Step-by-step implementation
1. Add `plan-path.ts` helper: derive `planDir` from `InstanceState` (`project.vcs ? worktree/.opencode/plans : Global.Path.data/plans`), export `isPlanFile(abs)` (`contains(planDir, abs) && endsWith .md`) and `isPlanDirOrFile(abs)` (dir itself included for `ls <dir>`).
2. In `agent.ts` plan block (before `user` merge): add `read: { .opencode/plans/*.md: allow, <relative global plans/*.md>: allow }`; add `external_directory: { <worktree>/.opencode/plans/*: allow }` alongside existing global entry. No `bash`/`glob`/`grep`/`list` entries. Mirror in `core/plugin/agent.ts` if needed.
3. In `shell.ts collect()`: after `argPath` resolution, drop `dirs` adds where `isPlanDirOrFile(resolved)`; skip `patterns.add(source)` only when command head in read-only set (`ls, dir, cat, head, tail, type, get-content`) AND every resolved path arg passes `isPlanDirOrFile` AND at least one path arg exists. Never skip pipes/redirects/subshells, zero-arg commands, writes, or mixed args.
4. Update `plan-mode.txt:57` wording to reflect silent peeks.
5. Add/extend tests: `Permission.evaluate(edit/read, .opencode/plans/foo.md, plan.permission)===allow`; global path allow; user `deny` on plan path wins; shell collect: `ls <planDir>`/`cat <planFile>` -> empty scan, `cat plan.md && rm -rf ~`/`ls` bare/`cat /etc/passwd` -> still prompts.
6. Run `bun typecheck` from `packages/opencode` + targeted permission/shell tests; manual matrix VCS x non-VCS x write/edit/cat/ls (no prompt) vs outside-plans + explicit deny (still prompt/deny).

## Risks / edge cases
- `bash` string matching is fragile (absolute vs relative, quotes, `~/`, `$HOME`, chained `;`/`&&`/`|`): mitigated by filtering on resolved absolute paths, not command strings.
- Over-allow risk if suffix/dir check omitted (e.g. `plans/auth.json`, `plans-evil/`): must check `.md` suffix + `contains()` not prefix-match.
- `worktree==="/"` skips worktree contains check: test explicitly.
- `glob`/`grep`/`list` ask on pattern strings not paths: leave alone, rely on external_directory check.
- Must not place exemption after user rules: user explicit deny must still win (allowlist approach preserves this).
- Non-VCS global plans need both relative-pattern (`edit`/`read`) and absolute `dir/*` (`external_directory`) forms.

## Testing strategy
- `bun typecheck` in `packages/opencode`.
- Permission unit tests: VCS + global edit/read allow, user-deny-wins.
- Shell collect unit tests: plan-only read peeks silent; chained/dynamic/bare/mixed/outside still prompt.
- Manual E2E matrix in plan mode: `write`/`edit` plan file, `ls` plans dir, `cat` plan file (silent) vs `cat /etc/passwd`, `ls ~`, bare `ls`, write outside plans, explicit user deny (prompt/deny preserved).

## Open questions

- Should `read`/`glob`/`grep`/`list` on plans dir also go silent, or only `bash` peeks + `edit`/`write`/`read` of the file? Plan assumes file + `ls` dir only.
- Non-VCS (`Global.Path.data/plans`) silent too, or VCS only? Plan covers both.
