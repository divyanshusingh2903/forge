# Remove packages/tui (full terminal UI), keep --mini

## Summary
Delete `packages/tui` (`@opencode-ai/tui`) entirely. Vendor the small subset `--mini` needs into `packages/opencode`, rewire bare `opencode` and non-mini `attach` to a "removed, use web/desktop" error, and delete TUI docs/specs. This matches NOTICE.md, which already declares removal of the terminal UI client.

## Context / Findings
- `packages/tui` is a private lib (`src/app.tsx` `run()`); sole consumer is `packages/opencode` (24 src files + 10 test/fixture files import `@opencode-ai/tui/*`). No other package, CI job, Dockerfile, or turbo task references it by name.
- Second terminal UI `packages/opencode/src/cli/cmd/run/*` (`--mini`, split-footer) is self-contained but imports TUI subpaths (keymap, editor, spinner, config, theme) — it must keep working, so those pieces get vendored, not deleted.
- Launchers today: bare `opencode` (`cli/cmd/tui.ts`) -> `cli/tui/layer.ts` -> TUI; `attach` (non-mini) -> TUI; `bun dev` -> TUI by default; `--mini` -> `runMini()` (keep).
- `@opencode-ai/plugin` `./tui` contract stays (public plugin API); only the host (`plugin/tui/*`) goes.
- Docs: `packages/web/src/content/docs/**/tui.mdx` (18 files); specs: `specs/tui-package.md` (+ `packages/opencode/specs/tui-plugins.md` if present).
- Build: `packages/opencode/script/build.ts` bundles the TUI worker + opentui parser worker; `bun.lock` needs regen via `bun install`.

## Approach
Vendor-first, then delete: copy what `--mini` needs into `packages/opencode/src/cli/mini/` while `packages/tui` still exists for diffing, repoint all imports, then delete the package, entrypoints, tests, docs. Keep `@opentui/*` deps (still used by `--mini`). No SDK regen (no Protocol/HttpApi change).

## Files affected
- Create `packages/opencode/src/cli/mini/` — vendored `keymap`, `editor` (+`editor-zed` if non-trivial), `spinner`, minimal `config` (`MiniConfig`), `theme-syntax` (`generateSyntax`/`generateSubtleSyntax` only); inline leaf utils (error/record/locale/logo/prompt-display/parsers-config) at existing shim sites.
- Edit `packages/opencode/src/cli/cmd/tui.ts` — keep `--mini` branch; non-mini prints removed-TUI error (exit 1, point to `opencode web`/desktop).
- Edit `packages/opencode/src/cli/cmd/attach.ts` — keep `attach --mini`; non-mini prints same error.
- Edit `packages/opencode/src/index.ts` + `package.json` `dev` script — `bun dev` no longer boots TUI (repoint to `web` or accept the error; decide at implementation).
- Delete `packages/opencode/src/cli/tui/` (`layer.ts`, `worker.ts`, `validate-session.ts`), `src/config/tui*.ts` (3 files), `src/plugin/tui/` (`internal.ts`, `runtime.ts`).
- Edit `packages/opencode/src/cli/cmd/run/*` (footer.*, runtime.boot/lifecycle, types.ts, theme.ts) — repoint to `../mini/*`.
- Edit `packages/opencode/package.json` (drop `@opencode-ai/tui`), `script/build.ts` (drop TUI worker + parser-worker entries + `dist/*/bin/tui` cleanup; keep Solid plugin only if `--mini` tsx needs it — verify by building).
- Delete `packages/tui/`; `packages/opencode/test/fixture/tui-*`, `test/config/tui.test.ts`, `test/cli/cmd/tui/*`, TUI-touching `test/cli/run/*` (enumerate via `rg -l @opencode-ai/tui`); fix `--mini` tests to new paths.
- Delete 18 `tui.mdx` docs + `specs/tui-package.md` (+ tui-plugins spec if present); edit `CONTRIBUTING.md`, `packages/opencode/AGENTS.md`, root `AGENTS.md`, `.opencode/agent/triage.md`, `script/raw-changelog.ts`, `.opencode/command/changelog.md`.
- Regenerate `bun.lock` via root `bun install`.

## Step-by-step implementation
1. Vendor `--mini` needs into `src/cli/mini/`; repoint `cli/cmd/run/*` imports; `bun typecheck` in `packages/opencode` passes with `packages/tui` still present.
2. Rewrite `cli/cmd/tui.ts` + `attach.ts` non-mini paths to the removed-TUI error; repoint `dev` script; verify `rg @opencode-ai/tui packages/opencode/src` shows only dead code.
3. Delete `src/cli/tui/`, `src/config/tui*.ts`, `src/plugin/tui/`, inline shim utils; re-verify the grep is empty (`@opentui` direct imports remain — expected).
4. Delete `packages/tui/`; drop dep from `packages/opencode/package.json`; `bun install` at root.
5. Update `script/build.ts` entries; prune tests/fixtures/snapshots; update docs/specs/guides/changelog mapping.
6. Verify (below).

## Risks / edge cases
- Keymap duplication drift between vendored copy and deleted original — header-comment the fork.
- `--mini` theme/syntax subtle changes — snapshot-test fallback + one dark/light palette.
- Solid bun-plugin removal must be proven by a successful build first; same for parser-worker defines (`rg OPENCODE_WORKER_PATH` must be empty).
- Third-party TUI plugins silently stop loading (host deleted, contract kept) — call out in changelog + error text.
- `tui.json` user configs get no migration — consider a one-time warning in `--mini` boot.
- Docs locales: delete all 18 mirrors or web i18n checks fail on orphaned routes.

## Testing strategy
- `rg "@opencode-ai/tui" packages/*/src packages/*/test packages/*/script` empty (outside plugin contract).
- `bun typecheck` in `packages/opencode` (never `tsc`); `bun test` from package dirs (never root).
- CLI smoke from `packages/opencode`: bare -> exit 1 + web/desktop message; `attach <url>` -> same error; `attach --mini` boots; `--mini` boots (prompt, keymap, spinner, theme); `web`/`serve` unaffected.
- Single-target `script/build.ts` succeeds with no `worker.ts`/parser-worker entries and no `dist/*/bin/tui`.
