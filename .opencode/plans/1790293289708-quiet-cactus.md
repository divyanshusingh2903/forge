# Make Plan Mode Produce Claude-Style Implementation Plans

## Context

Experimental plan mode creates a durable Markdown file and injects its workflow from `packages/opencode/src/session/prompt/plan-mode.txt`. The existing instructions require research, critical paths, and verification, but do not prescribe the concrete reasoning, scope, and file-level structure present in the selected reference plans in `/home/divyanshu-singh/.claude/plans/`.

The reference plans consistently establish the current behavior with verified symbols/locations, record consequential decisions and rejected alternatives, specify changes file by file, name deliberate exclusions, and give executable verification steps. Their depth scales with the request: the small handler fix remains compact, while multi-service work adds cross-boundary reasoning and explicit risks.

The current Phase 2 instruction also tells the plan agent to launch a `general` subagent, while the native `plan` agent denies `task:general` in `packages/opencode/src/agent/agent.ts`. This can interrupt planning rather than improving the final plan. The corrected workflow must use the plan agent's researched findings directly unless a read-only exploration task is needed.

## Approach

1. Update `packages/opencode/src/session/prompt/plan-mode.txt` to replace the generic Phase 4 guidance with a required Claude-style plan shape:
   - A specific `#` title and `## Context` that explains the observed behavior/problem, cites relevant paths plus symbols or approximate locations, and distinguishes confirmed findings from assumptions.
   - `## Design decisions` only for consequential choices, including the selected option and why alternatives are not used.
   - `## Changes`, organized by affected component or file, with the exact files, target symbols, behavioral changes, data/API implications, and any related test updates. Preserve the compact form for small changes instead of inventing artificial detail.
   - `## Out of scope` for intentionally excluded adjacent work and known limitations when relevant; state that none exist when a boundary needs to be explicit.
   - `## Verification` as concrete commands and/or manual scenarios, including expected observable outcomes and negative/regression cases where the change has risk.
   - `## Files touched` as a final inventory separating new, modified, and deliberately untouched files where that clarification prevents scope drift.
2. Strengthen the prompt's quality constraints so plan sections are backed by repository research rather than generic restatements, avoid unsupported line-number precision, retain decisions made during user clarification, and revise the existing plan incrementally without discarding valid prior findings.
3. Remove the unusable `general`-subagent requirement from Phase 2 and direct the plan agent to synthesize the exploration results itself. Keep the existing exploration delegation limits and read-only rules unchanged.
4. Add a focused prompt-contract test, adjacent to the existing session prompt tests, that imports `plan-mode.txt` and asserts the durable requirements rather than snapshotting prose. Cover the required heading contract, evidence/file-level specificity, proportional detail, scope boundaries, concrete verification, incremental revision, and `present_plan` sequencing. This guards future prompt rewrites from silently reducing plan quality while avoiding brittle generated-LLM-output snapshots.
