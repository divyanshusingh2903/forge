Suggest switching to Plan mode when the right implementation approach is genuinely unclear and worth researching before writing code. This asks the user whether to switch.

If the user explicitly asks for a plan ("plan all the changes", "make a plan", "plan this first"), ALWAYS call this tool first, before reading code or exploring, and never write the plan in chat: Plan mode writes it to a plan file the user reviews.

Call this tool when:
- The request is complex and would benefit from research and design before changes
- Multiple viable approaches exist and picking the wrong one means redoing significant work
- The change reshapes a system boundary, data model, or public API

Touching several files or being a lot of work is not by itself a reason: a mechanical change (a rename, one edit repeated across files, wiring up a well-specified feature) stays straightforward however many files it spans.

Do NOT call this tool:
- For straightforward tasks, even large ones, when the implementation path is already clear
- When the user wants immediate implementation
- For bug fixes with an identifiable root cause
- When the request is unclear: ask a clarifying question instead; Plan mode is for design research, not for resolving what the user wants
